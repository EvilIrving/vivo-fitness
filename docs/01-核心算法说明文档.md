# 健身计数助手 - 核心算法说明文档

> 本文档为 **Apple Watch（watchOS）** 实现提供依据，采用与框架无关的伪代码描述。  
> **事实来源优先级**：本文件与 `docs/03`、`docs/02` 一致；若与旧版实现代码有出入，以文档为准迭代代码。

---

## 核心设计理念

### 问题定义

- **用户先选择动作**，算法只做一件事：在当前动作下，判断「是否完成了一次可接受的重复」，并计数。**不做**「全库动作分类」。
- **产品边界**：并非所有训练动作都能在手腕传感器上形成稳定、可重复的观测轴；第一版只收录 **5～8 个** 经实测高置信度的动作，宁可少而稳。

### 观测上的现实

- Watch **没有**可靠的绝对空间位置；位置类信息只能通过加速度、重力向量、陀螺仪与姿态变化**间接**推断。
- **滤波、方向变化、最小间隔** 的目的不是假设「动作必须规律」，而是 **抗噪、抗顶点微抖、抗误触发**；疲劳导致变慢、停顿、幅度变小，应在产品定义与算法上被容忍。
- **积分求位移** 会漂移，仅允许在 **短周期、带重置** 的前提下作为可选辅助，不能作为唯一判据。

### 个体化策略（以当前共识为准）

1. **个人动作模板校准（主路径）**  
   在正式计数组之前，引导用户完成一小段采样（如：起始姿势静止约 2 秒 → 连续 5～10 次标准行程 → 结束静止约 2 秒）。从样本中估计该用户、该动作下的 **低位区 / 高位区（或展开区 / 闭合区）** 与特征轴上的容忍带，形成 **个体模板**。

2. **组内自适应阈值（辅路径）**  
   在已有模板基础上，对本组已完成的若干次进行统计，**缓慢** 放宽或收紧有效行程与阈值，以应对力竭时幅度变小。**不应** 把「仅组内前几下」当作唯一个体化来源（否则每组冷启动误差大）。

3. **换握法 / 换左右手 / 换佩戴方式**  
   视为 **不同的有效配置**：应提示用户重新校准或选用不同「动作配置」，而不是指望单一模板覆盖所有情况。

### 完成判定的核心抽象

- 用 **宽容状态机 + 双区间闭环** 描述一次重复：从 **A 区** 出发，经运动进入 **B 区**，再 **回到 A 区**，记 1 次。  
- A/B 在工程上由 **重力分量、俯仰/航向相关特征、角速度模式、或主监测轴上的包络** 等定义，按动作选型；**不要求** 固定周期时长，但可设 **极长的最大停留时间** 防止状态卡死。

## 1. 传感器与数据

### 1.1 输入

使用 Core Motion（或等价 API）在 **训练会话已开启、用户已选动作** 期间采集，建议包括：

- `userAcceleration`（用户加速度，已去重力）
- `gravity`（重力方向，用于姿态/主特征轴）
- `rotationRate`（陀螺仪）

### 1.2 采样率

- **推荐约 50 Hz**（每 20 ms 一次）作为力训计数与滤波的折中；可按功耗略调低，但不宜长期低于约 40 Hz（若平台允许）。
- 文档中若出现「约 16 Hz」等旧表述，**以 50 Hz 级为准**。

### 1.3 坐标系

表盘朝上、常规佩戴时，典型 Apple Watch 轴向如下（实现以系统文档为准）：

```
     +Y (向指尖方向)
      ↑
      │
      ●───→ +X
     /
    +Z (表盘法向向外)
```

### 1.4 数据结构（示意）

```
STRUCT SensorReading:
    x, y, z: Float
    timestamp: Integer   // 毫秒
END STRUCT

STRUCT FusedSensorData:
    rawAcc, rawGyro: SensorReading
    filteredAcc, filteredGyro: SensorReading
    // 派生：模长、重力在选定轴上的投影、姿态相关标量等
    features: { ... }
    timestamp: Integer
END STRUCT
```

## 2. 数据滤波

原始数据含高频噪声，需低通处理后再进入状态机。

### 2.1 滑动均值（示例）

```
FUNCTION movingAverage(buffer, windowSize):
    w = MIN(windowSize, buffer.length)
    window = buffer[-w:]
    RETURN mean(window.x), mean(window.y), mean(window.z)
END FUNCTION
```

窗口越大降噪越强、延迟越大；典型窗口 3～7 个采样点（按采样率调）。

### 2.2 向量模长

```
FUNCTION magnitude(x, y, z):
    RETURN SQRT(x*x + y*y + z*z)
END FUNCTION
```

## 3. 个人动作模板校准

### 3.1 目的

将计数从「与统一标准动作比对」变为「与 **该用户当前做法** 的模板比对」，容忍疲劳与速度变化，只要仍保持 **同一闭环结构**。

### 3.2 推荐流程（可随产品微调）

1. **说明佩戴**：单侧手腕、表带松紧适中、选定左右手与表冠朝向（与产品约束一致）。  
2. **起始静止**：约 2 秒，采集特征用于 **A 区（低位/展开）** 初值。  
3. **引导重复**：连续完成 **5～10 次** 完整动作（次数可配置）。  
4. **结束静止**：约 2 秒，巩固 A 区。  
5. **估计模板**：  
   - 在每个重复周期内提取主特征序列；  
   - 用分位数或聚类得到 **A 区、B 区** 在特征轴上的区间与方差；  
   - 得到 **最小有效行程**（A→B 或特征变化幅度）与 **防抖间隔**（两次计数之间的最短时间）。

### 3.3 模板内容（示意）

```
STRUCT MotionTemplate:
    actionCode: String
    primaryFeature: String       // 如 "gravityAlongX" | "pitchProxy" | "accZ" | "gyroY" ...
    zoneA: { min: Float, max: Float }   // 低位 / 展开
    zoneB: { min: Float, max: Float }   // 高位 / 夹紧
    minStroke: Float            // 最小有效行程（同特征单位）
    minIntervalMs: Integer      // 两次计数最小间隔
    maxRepDurationMs: Integer   // 单次闭环允许的上限（防卡死，宜宽）
    calibratedAt: Integer
    wearSide: String            // leftWrist | rightWrist
END STRUCT
```

### 3.4 准入

若校准段内无法分离出稳定双区间（方差过大或重叠），应 **提示失败** 并建议调整佩戴或换动作，**不得** 强行入库计数。

## 4. 区间状态机与完成判定

### 4.1 状态（逻辑名）

与旧版「仅峰值」叙述相比，**以区间与闭环为准**：

```
ENUM RepState:
    IN_ZONE_A      // 在 A 区（低位/展开）
    TOWARD_B       // 已离开 A，向 B 运动
    IN_ZONE_B      // 进入 B 区（高位/闭合）
    RETURNING_A    // 从 B 返回 A
END ENUM
```

一次有效重复：**IN_ZONE_A → TOWARD_B → IN_ZONE_B → RETURNING_A → IN_ZONE_A**，且满足模板中的 **最小行程、最短时间间隔、最大单次时长**。

### 4.2 主特征提取

```
FUNCTION extractFeature(fused, template):
    // 示例：按动作选择重力投影、单轴加速度或角速度包络
    SWITCH template.primaryFeature:
        CASE "gravityAlongX": ...
        CASE "accZ": RETURN ABS(fused.filteredAcc.z)
        ...
    END SWITCH
END FUNCTION
```

具体轴与特征由 **动作定义表** 规定，且须与校准数据一致。

### 4.3 区间判定

```
FUNCTION inZone(value, zone):
    RETURN value >= zone.min AND value <= zone.max
END FUNCTION
```

区间可随组内自适应 **缓慢形变**（见第 5 节），避免第 1 组与第 4 组幅度差异导致漏计。

### 4.4 与「加速度峰值法」的关系

早期文档以「去程→峰值→回程」+ 加速度阈值描述，实现上可映射为：**峰值区 = 进入 B 区或特征极大段**；**回程 = 离开 B 向 A 回归**。新文档强调 **A/B 区间与闭环**，峰值只是可选的中间标志。

### 4.5 时间窗

- **min**：仅用于 **防抖**（极短，如 0.15～0.4 s 量级，依采样率定），**不是**「一次动作必须快于某值」。  
- **max**：宜 **宽**（数秒～数十秒），防止力竭慢速被整体否决；超时则复位状态机并可选日志。

## 5. 组内自适应与动态基线

### 5.1 作用

在模板基础上，用本组已确认重复的样本更新：

- B 区中心或边界（幅度变小时收窄检测）  
- 或等价地更新「有效阈值」与 `minStroke` 的下界  

### 5.2 原则

- 学习样本来自 **已成功计数** 的重复，避免把噪声当「高质量」。  
- 限制历史长度与单次调整幅度，防止漂移导致误计。  
- **新一组** 可重置「仅本组学习缓冲区」，但 **保留模板** 不丢失（除非用户重校准）。

### 5.3 伪代码片段

```
VAR recentPeakFeatures: Array<Float> = []

FUNCTION onRepCounted(featurePeak: Float):
    recentPeakFeatures.push(featurePeak)
    IF recentPeakFeatures.length > MAX_RECENT THEN
        recentPeakFeatures.shift()
    END IF
    adjustZonesFromRecent()
END FUNCTION
```

## 6. 位移积分增强（可选）

### 6.1 定位

当 **向心段加速度明显** 而 **回程极慢** 时，纯包络可能漏检；可对 **主方向** 做 **短周期** 速度/位移积分作 OR 条件。

### 6.2 约束

- 仅在 **单次重复状态机激活期间** 积分，**每次计数或超时后清零**。  
- 设噪声门限，忽略极小加速度。  
- **不得** 依赖米级绝对位移作为唯一真理。

## 7. 无效数据判定

```
CONST VALIDATION_RANGE = {
    ACCELEROMETER_MAX: 200,
    GYROSCOPE_MAX: 2000
}

FUNCTION validateSample(acc, gyro):
    IF any NaN THEN RETURN FALSE
    IF out of VALIDATION_RANGE THEN RETURN FALSE
    RETURN TRUE
END FUNCTION
```

无效样本丢弃，不进入缓冲区。

## 8. 数据存储设计

保留原结构化设计思路：训练记录、组数据、当前会话、用户统计；可增加字段：

- `motionTemplateId` / 校准时间戳  
- `wearSide`  
- `appVersion`

存储键与 JSON 示例见历史版本，实现可选用 UserDefaults、文件或 Core Data。

## 10. 开发测试环境

### 10.1 模拟器

- 可完整验证 **SwiftUI 流程、状态管理、本地存储、假数据注入**（回放录制序列测试状态机）。  
- **无法** 提供真实 Core Motion 流，**无法** 验证噪声、佩戴差异与功耗。

### 10.2 真机

- **计数算法、阈值、模板校准、触觉体验** 必须在 **真实 Apple Watch** 上迭代。  
- 典型链路：**Mac（Xcode）→ iPhone（配对与调试桥接）→ Apple Watch**。开发阶段需 iPhone 与手表配对并保持连接；无需用户全程操作手机，但手机需在线。

### 10.3 建议节奏

先模拟器搭建架构与回放测试，**尽早** 上真机调参；产品成败高度依赖真实数据，而非界面代码量。

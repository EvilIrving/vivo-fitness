# 健身计数助手 - 核心算法说明文档

> 本文档为 Apple Watch 平台迁移准备，采用与框架无关的伪代码描述核心算法逻辑。

---

## 核心设计理念

**本算法的核心前提：用户先选择动作类型，算法只需识别"动作是否完成一次"，不需要识别"动作是什么"。**

这一设计大幅简化了算法复杂度，将问题从"多分类识别"简化为"单一动作的完成检测"。

### 核心难点

1. **幅度衰减问题**：一组动作中，前几个力气充足、幅度大、信号明显容易识别；后面力竭时幅度变小、信号弱、难以识别
2. **动作完整性**：每次动作都是"有去有回"的完整周期，需要检测完整的运动闭环
3. **个体差异**：不同用户的动作幅度、速度存在差异，需要自适应调整

### 解决方案

1. **自适应阈值**：基于动态基线，根据用户当前组的表现实时调整识别阈值
2. **去回检测**：检测完整的"离开 → 峰值 → 返回"周期，确保动作完整性
3. **渐进式学习**：从每组前几次高质量动作学习特征，用于识别后续低幅度动作

## 1. 传感器使用说明

### 1.1 算法背景

**重要：算法不需要识别动作类型，只需要检测用户选定动作的完成次数。**

用户在开始训练前已选择具体动作（如"杠铃卧推"），算法只需：
1. 根据预设的动作特征参数监测传感器数据
2. 检测符合该动作模式的完整周期
3. 每检测到一次完整周期，计数 +1

```
Apple Watch 坐标系（表盘朝上时）:
     +Y (向指尖方向)
      ↑
      │
      │
      ●───→ +X (向右侧方向)
     /
    ↙
   +Z (向表盘外/天空方向)
```

### 1.4 采样频率

```
SENSOR_INTERVAL = "ui"  // 对应约 60ms/次

  采样频率 f = 1000ms / 60ms ≈ 16.67 Hz
  
Apple Watch 建议:
  CoreMotion 默认采样率: 50-100 Hz

## 2. 数据滤波算法

### 2.1 算法背景

原始传感器数据包含高频噪声（设备振动、肌肉颤抖等），需要通过滤波平滑数据以提取有意义的运动特征。

### 2.2 滑动窗口均值滤波

#### 输入输出定义

```
/**
 * 滑动窗口均值滤波
 * 
 * @input  dataBuffer: Array<SensorReading>  // 传感器数据缓冲区
 * @input  windowSize: Integer               // 滑动窗口大小
 * @output FilteredReading                   // 滤波后的数据点
 * 
 * 约束条件:
 *   - windowSize >= 1
 *   - dataBuffer.length >= 1
 */
```

#### 算法伪代码

```
FUNCTION applyMovingAverageFilter(dataBuffer, windowSize):
    // 边界条件处理
    IF dataBuffer.length == 0 THEN
        RETURN { x: 0, y: 0, z: 0 }
    END IF
    
    // 实际窗口大小取较小值
    actualWindowSize = MIN(windowSize, dataBuffer.length)
    
    // 取最近 N 个数据点
    window = dataBuffer.slice(-actualWindowSize)
    
    // 计算各轴均值
    sumX = 0, sumY = 0, sumZ = 0
    FOR EACH reading IN window:
        sumX += reading.x
        sumY += reading.y
        sumZ += reading.z
    END FOR
    
    RETURN {
        x: sumX / actualWindowSize,
        y: sumY / actualWindowSize,
        z: sumZ / actualWindowSize
    }
END FUNCTION
```

#### 数学证明

设滑动窗口内的 n 个采样值为 $x_1, x_2, ..., x_n$，滤波输出为：

$$\bar{x} = \frac{1}{n}\sum_{i=1}^{n}x_i$$

**降噪效果证明：**

假设真实信号为 $s$，噪声为 $\epsilon_i$（独立同分布，均值为 0，方差为 $\sigma^2$），则：

$$x_i = s + \epsilon_i$$

滤波后：

$$\bar{x} = \frac{1}{n}\sum_{i=1}^{n}(s + \epsilon_i) = s + \frac{1}{n}\sum_{i=1}^{n}\epsilon_i$$

噪声部分的方差：

$$Var\left(\frac{1}{n}\sum_{i=1}^{n}\epsilon_i\right) = \frac{\sigma^2}{n}$$

**结论：** 滤波后噪声方差降低为原来的 $1/n$，窗口越大降噪效果越好，但会增加信号延迟。

#### 配置参数

```
CONST WINDOW_SIZE = 5           // 滤波窗口大小
CONST SENSOR_BUFFER_SIZE = 100  // 传感器数据缓冲区大小
```

### 2.3 向量模长计算

```
/**
 * 计算三维向量的欧几里得模长
 * 
 * @input  x, y, z: Float  // 三轴分量
 * @output Float           // 向量模长
 */
FUNCTION calculateMagnitude(x, y, z):
    RETURN SQRT(x² + y² + z²)
END FUNCTION

// 数学定义: ||v|| = √(x² + y² + z²)
```

## 3. 动作完成检测算法

### 3.1 算法背景

**核心原则：不识别动作类型，只检测动作完成。**

由于用户已预先选择动作类型，算法的任务简化为：
- 检测符合预设参数的**完整运动周期**
- 每个完整周期 = 一次动作完成 = 计数 +1

**完整运动周期定义：**
```
一次完整动作 = "去程" + "回程"

去程：从静止状态离开，到达运动峰值
回程：从峰值返回，回归静止状态

示例（杠铃卧推）：
  静止 → 推起（去程）→ 最高点（峰值）→ 下落（回程）→ 静止
```

### 3.2 状态机设计

```
// 动作完成检测状态枚举
ENUM DetectionState:
    BASELINE        // 基线状态，等待运动开始
    DEPARTING       // 去程：检测到离开基线，正在远离
    PEAK_ZONE       // 峰值区：到达运动极值附近
    RETURNING       // 回程：从峰值返回，正在接近基线
    // 回到 BASELINE 时，若完成完整周期，触发计数
END ENUM
```

### 3.3 动作配置参数

```
// 每种动作的检测参数配置
// 注意：这些参数用于"完成检测"，不是"类型识别"
STRUCT DetectionParams:

    initialPeakThreshold: Float  // 初始峰值阈值（用于前几次动作）
    minPeakRatio: Float          // 最小峰值比例（相对于学习到的平均峰值）
    timeWindow: {
        min: Float,              // 最小动作时长（秒）
        max: Float               // 最大动作时长（秒）
    }
    baselineWindow: Float        // 基线判定范围
    adaptiveEnabled: Boolean     // 是否启用自适应阈值
END STRUCT

// 示例：杠铃卧推参数（用于完成检测，非类型识别）
BENCH_PRESS_PARAMS = {
    primaryAxis: "z",              // Z轴加速度为主
    initialPeakThreshold: 1.5,     // 初始阈值 1.5 m/s²
    minPeakRatio: 0.4,             // 最低可接受峰值为平均值的 40%

### 3.4 核心检测算法

#### 3.4.1 主值提取

```
FUNCTION extractPrimaryValue(fusedData, params):
    axis = params.primaryAxis
    acc = fusedData.filtered.acc
    
    SWITCH axis:
        CASE "z":
            RETURN ABS(acc.z)
        CASE "y":
            RETURN ABS(acc.y)
        CASE "x":
            RETURN ABS(acc.x)
        CASE "magnitude":
            RETURN fusedData.features.accMagnitude
        DEFAULT:
            RETURN fusedData.features.accMagnitude
    END SWITCH
END FUNCTION
```

#### 3.4.2 完整周期检测算法

```
/**
 * 动作完成检测器
 * 
 * 核心逻辑：检测 "去程 → 峰值 → 回程" 的完整周期
 * 
 * 关键特性：
 * 1. 不识别动作类型（用户已选择）
 * 2. 自适应阈值（应对力竭时幅度衰减）
 * 3. 完整周期验证（有去有回）
 */

// 状态变量
STATE:
    currentState: DetectionState = BASELINE
    departureTime: Integer = 0           // 离开基线时间
    peakValue: Float = 0                 // 当前周期峰值
    peakTime: Integer = 0                // 峰值时间
    baselineValue: Float = 0             // 动态基线值
    
    // 自适应学习
    learnedPeaks: Array<Float> = []      // 学习到的峰值历史
    adaptiveThreshold: Float = 0         // 自适应阈值
    completedCount: Integer = 0          // 已完成计数

FUNCTION processDetection(fusedData):
    value = extractPrimaryValue(fusedData, params)
    timestamp = fusedData.timestamp
    
    // 更新动态基线
    updateBaseline(value)
    
    // 获取当前有效阈值
    threshold = getEffectiveThreshold()
    
    SWITCH currentState:
        CASE BASELINE:
            handleBaseline(value, timestamp, threshold)
        CASE DEPARTING:
            handleDeparting(value, timestamp, threshold)
        CASE PEAK_ZONE:
            handlePeakZone(value, timestamp, threshold)
        CASE RETURNING:
            handleReturning(value, timestamp, threshold)
    END SWITCH
END FUNCTION
```

#### 3.4.3 各状态处理逻辑

```
// ========== 基线状态：等待去程开始 ==========
FUNCTION handleBaseline(value, timestamp, threshold):
    departureThreshold = threshold * 0.5
    
    IF value > baselineValue + departureThreshold THEN
        // 检测到离开基线，开始去程
        currentState = DEPARTING
        departureTime = timestamp
        peakValue = value
        LOG("去程开始")
    END IF
END FUNCTION

// ========== 去程状态：追踪峰值 ==========
FUNCTION handleDeparting(value, timestamp, threshold):
    // 持续追踪最大值
    IF value > peakValue THEN
        peakValue = value
        peakTime = timestamp
    END IF
    
    // 检测是否开始回落（进入峰值区）
    IF value < peakValue * 0.85 AND peakValue >= threshold THEN
        // 峰值足够且开始回落，进入峰值区
        currentState = PEAK_ZONE
        LOG("进入峰值区，峰值: " + peakValue)
    END IF
    
    // 超时保护
    elapsed = (timestamp - departureTime) / 1000
    IF elapsed > params.timeWindow.max THEN
        resetToBaseline("去程超时")
    END IF
END FUNCTION

// ========== 峰值区状态：确认回程开始 ==========
FUNCTION handlePeakZone(value, timestamp, threshold):
    returnThreshold = peakValue * 0.6
    
    IF value < returnThreshold THEN
        // 确认进入回程
        currentState = RETURNING
        LOG("回程开始")
    END IF
    
    // 如果又开始上升，可能是多峰动作，更新峰值
    IF value > peakValue THEN
        peakValue = value
        peakTime = timestamp
    END IF
END FUNCTION

// ========== 回程状态：等待回归基线 ==========
FUNCTION handleReturning(value, timestamp, threshold):
    // 检测是否回归到基线附近
    IF value <= baselineValue + params.baselineWindow THEN
        // 回归基线，验证完整周期
        duration = (timestamp - departureTime) / 1000
        
        IF duration >= params.timeWindow.min AND duration <= params.timeWindow.max THEN
            // ✅ 完整周期确认！触发计数
            onMotionComplete(duration, peakValue)
        ELSE
            LOG("时间窗口验证失败: " + duration + "秒")
        END IF
        
        // 重置到基线状态
        resetToBaseline("周期完成")
    END IF
    
    // 如果又开始上升，可能用户中途改变
    IF value > peakValue * 0.7 THEN
        // 回到峰值区继续监测
        currentState = PEAK_ZONE
    END IF
END FUNCTION

// ========== 重置到基线 ==========
FUNCTION resetToBaseline(reason):
    currentState = BASELINE
    peakValue = 0
    departureTime = 0
    LOG("重置到基线: " + reason)
END FUNCTION
```

### 3.5 动作完成回调

```
FUNCTION onMotionComplete(duration, peakValue):
    completedCount += 1
    
    // 学习此次峰值（用于自适应）
    IF params.adaptiveEnabled THEN
        learnPeak(peakValue)
    END IF
    
    LOG("动作完成 #" + completedCount + " 耗时: " + duration + "秒，峰值: " + peakValue)
    
    // 触发回调
    IF onCountCallback != null THEN
        onCountCallback({
            count: completedCount,
            duration: duration,
            peakValue: peakValue,
            timestamp: NOW()
        })
    END IF
END FUNCTION
```

## 4. 自适应阈值系统

### 4.1 设计背景

**核心问题：力竭时动作幅度衰减**

```
典型场景（12次一组）：
  第 1-4 次：力气充足，幅度大（峰值 2.0-2.5 m/s²）→ 容易识别
  第 5-8 次：开始疲劳，幅度中（峰值 1.5-2.0 m/s²）→ 可以识别
  第 9-12次：力竭阶段，幅度小（峰值 0.8-1.2 m/s²）→ 难以识别

如果使用固定阈值（如 1.5 m/s²）：
  - 前 8 次能识别
  - 后 4 次可能漏检 ❌
```

### 4.2 解决方案：渐进式自适应

```
策略：从前几次高质量动作中学习，动态降低阈值

学习阶段（前 3-5 次）：
  - 记录每次完成动作的峰值
  - 计算平均峰值作为基准

适应阶段（后续动作）：
  - 允许的最低峰值 = 平均峰值 × minPeakRatio
  - 随着疲劳，阈值自动放宽
  - 但仍保持最低门槛，避免误检
```

### 4.3 自适应阈值算法

```
// 自适应阈值配置
CONST ADAPTIVE_CONFIG = {
    LEARNING_COUNT: 3,           // 学习前 N 次动作
    MIN_PEAK_RATIO: 0.4,         // 最低峰值比例（平均值的 40%）
    ABSOLUTE_MIN_THRESHOLD: 0.5, // 绝对最低阈值（m/s²）
    DECAY_FACTOR: 0.95,          // 每次动作后的衰减因子
    MAX_HISTORY: 10              // 保留最近 N 次峰值
}

// 学习到的峰值历史
VAR learnedPeaks: Array<Float> = []
VAR averagePeak: Float = 0
VAR currentThreshold: Float = initialPeakThreshold

// ========== 学习峰值 ==========
FUNCTION learnPeak(peakValue):
    // 添加到历史
    learnedPeaks.push(peakValue)
    
    // 限制历史长度
    IF learnedPeaks.length > ADAPTIVE_CONFIG.MAX_HISTORY THEN
        learnedPeaks.shift()
    END IF
    
    // 重新计算平均峰值
    averagePeak = calculateAveragePeak()
    
    // 更新自适应阈值
    updateAdaptiveThreshold()
END FUNCTION

// ========== 计算平均峰值 ==========
FUNCTION calculateAveragePeak():
    IF learnedPeaks.length == 0 THEN
        RETURN initialPeakThreshold
    END IF
    
    sum = 0
    FOR EACH peak IN learnedPeaks:
        sum += peak
    END FOR
    
    RETURN sum / learnedPeaks.length
END FUNCTION

// ========== 更新自适应阈值 ==========
FUNCTION updateAdaptiveThreshold():
    IF learnedPeaks.length < ADAPTIVE_CONFIG.LEARNING_COUNT THEN
        // 学习阶段：使用初始阈值
        currentThreshold = params.initialPeakThreshold
    ELSE
        // 适应阶段：基于平均峰值计算
        adaptiveThreshold = averagePeak * ADAPTIVE_CONFIG.MIN_PEAK_RATIO
        
        // 应用衰减因子（随疲劳进一步降低）
        fatigueAdjustment = POWER(ADAPTIVE_CONFIG.DECAY_FACTOR, completedCount - ADAPTIVE_CONFIG.LEARNING_COUNT)
        adaptiveThreshold = adaptiveThreshold * fatigueAdjustment
        
        // 确保不低于绝对最低阈值
        currentThreshold = MAX(adaptiveThreshold, ADAPTIVE_CONFIG.ABSOLUTE_MIN_THRESHOLD)
    END IF
    
    LOG("阈值更新: " + currentThreshold + " (平均峰值: " + averagePeak + ")")
END FUNCTION

// ========== 获取有效阈值 ==========
FUNCTION getEffectiveThreshold():
    IF NOT params.adaptiveEnabled THEN
        RETURN params.initialPeakThreshold
    END IF
    
    RETURN currentThreshold
END FUNCTION
```

结论：通过自适应阈值，即使力竭时峰值降至 0.6（初始的 26%），仍能正确识别
```

### 4.5 动态基线计算

```
// 基线用于判断是否"回归静止"
// 使用滑动窗口计算动态基线，适应不同姿势

CONST BASELINE_CONFIG = {
    WINDOW_SIZE: 20,            // 基线计算窗口
    UPDATE_INTERVAL: 100,       // 更新间隔（ms）
    STABLE_THRESHOLD: 0.2       // 稳定判定阈值
}

VAR baselineBuffer: Array<Float> = []
VAR dynamicBaseline: Float = 0

FUNCTION updateBaseline(value):
    // 只在静止状态更新基线
    IF currentState != BASELINE THEN
        RETURN
    END IF
    
    baselineBuffer.push(value)
    IF baselineBuffer.length > BASELINE_CONFIG.WINDOW_SIZE THEN
        baselineBuffer.shift()
    END IF
    
    // 计算平均值作为基线
    IF baselineBuffer.length >= 5 THEN
        sum = 0
        FOR EACH v IN baselineBuffer:
            sum += v
        END FOR
        dynamicBaseline = sum / baselineBuffer.length
    END IF
END FUNCTION
```

## 5. 无效数据判定

### 5.1 算法背景

传感器可能产生异常数据（硬件故障、极端干扰、数值溢出等），需要在处理前过滤掉这些无效数据。

### 5.2 验证范围定义

```
CONST VALIDATION_RANGE = {
    ACCELEROMETER_MAX: 200,    // 加速度最大值 ±200 m/s² (约±20g)
    GYROSCOPE_MAX: 2000        // 陀螺仪最大值 ±2000 °/s
}
```

### 5.3 加速度计数据验证

```
/**
 * 验证加速度计数据有效性
 * 
 * @input  data: SensorReading  // 原始加速度数据
 * @output Boolean              // true=有效, false=无效
 * 
 * 边界条件:
 *   1. 数据对象不能为 null
 *   2. x, y, z 必须是有效数字（非 NaN）
 *   3. 各轴绝对值不超过最大范围
 */
FUNCTION validateAccelerometerData(data):
    // 检查数据对象存在性
    IF data == null OR typeof(data) != "object" THEN
        RETURN FALSE
    END IF
    
    x = data.x
    y = data.y
    z = data.z
    
    // 检查是否为有效数字
    IF isNaN(x) OR isNaN(y) OR isNaN(z) THEN
        RETURN FALSE
    END IF
    
    // 范围检查
    maxAcc = VALIDATION_RANGE.ACCELEROMETER_MAX
    IF ABS(x) > maxAcc OR ABS(y) > maxAcc OR ABS(z) > maxAcc THEN
        RETURN FALSE
    END IF
    
    RETURN TRUE
END FUNCTION
```

### 5.4 陀螺仪数据验证

```
/**
 * 验证陀螺仪数据有效性
 * 
 * @input  data: SensorReading  // 原始陀螺仪数据
 * @output Boolean              // true=有效, false=无效
 */
FUNCTION validateGyroscopeData(data):
    // 检查数据对象存在性
    IF data == null OR typeof(data) != "object" THEN
        RETURN FALSE
    END IF
    
    x = data.x
    y = data.y
    z = data.z
    
    // 检查是否为有效数字
    IF isNaN(x) OR isNaN(y) OR isNaN(z) THEN
        RETURN FALSE
    END IF
    
    // 范围检查
    maxGyro = VALIDATION_RANGE.GYROSCOPE_MAX
    IF ABS(x) > maxGyro OR ABS(y) > maxGyro OR ABS(z) > maxGyro THEN
        RETURN FALSE
    END IF
    
    RETURN TRUE
END FUNCTION
```

### 5.5 无效数据处理策略

```
FUNCTION onSensorData(rawData):

        // 丢弃无效数据，不加入缓冲区

```
/**
 * 生成唯一训练记录ID
 * 
 * @output String  // 格式: rec_YYYYMMDD_XXX
 */
FUNCTION generateRecordId():
    now = getCurrentDateTime()
    
    dateStr = now.year + 
              padZero(now.month, 2) + 
              padZero(now.day, 2)
    
    randomStr = padZero(RANDOM(0, 999), 3)
    
    RETURN "rec_" + dateStr + "_" + randomStr
END FUNCTION
```

### 6.4 核心存储操作

// ========== 保存训练记录 ==========
ASYNC FUNCTION saveRecord(record):
    TRY
        records = AWAIT getAllRecords()
        
        IF record.recordId == null THEN
            record.recordId = generateRecordId()
        END IF
        IF record.timestamp == null THEN
            record.timestamp = NOW()
        END IF
        
        records.push(record)
        
        AWAIT storage.set(
            key: STORAGE_KEYS.TRAINING_RECORDS,
            value: JSON.stringify(records)
        )
        
        RETURN TRUE
    CATCH error
        LOG("保存失败: " + error)
        RETURN FALSE
    END TRY
END FUNCTION

// ========== 获取所有记录 ==========
ASYNC FUNCTION getAllRecords():
    TRY
        data = AWAIT storage.get(key: STORAGE_KEYS.TRAINING_RECORDS)
        records = JSON.parse(data)
        RETURN isArray(records) ? records : []
    CATCH
        RETURN []
    END TRY
END FUNCTION

## 附录 C: 算法设计原则

### C.1 为什么不识别动作类型？

```
传统方案（需要识别动作类型）：
  问题1: 需要训练复杂的分类模型
  问题2: 相似动作容易混淆（如卧推 vs 肩推）
  问题3: 个体差异导致识别率不稳定
  问题4: 手表算力有限，复杂模型耗电快

本方案（预设动作 + 完成检测）：
  优势1: 算法简单，状态机即可实现
  优势2: 用户选择动作，100% 准确
  优势3: 专注于检测完成，准确率高
  优势4: 轻量级，省电
```

### C.2 自适应阈值的必要性

```
固定阈值的问题：
  - 阈值过高：力竭时漏检
  - 阈值过低：静止时误检

自适应阈值的优势：
  - 从用户实际动作学习
  - 随疲劳自动调整
  - 个性化适应不同用户
```

### C.3 完整周期检测的必要性

```
仅检测峰值的问题：
  - 颤抖、调整姿势可能产生假峰值
  - 无法确认用户真正完成了动作

去回周期检测的优势：
  - 必须有离开 + 返回，排除假信号
  - 时间窗口验证，排除异常速度
  - 与真实动作模式一致
```
